## 1. 개발 · 배포 · 서버 운영 전략

### 1) 코드 및 브랜치 관리 (GitHub `MUSICKING` 단일 레포)
- **`main` 브랜치:** 현재 원스토어(H5) 및 웹 라이브 버전 유지 (V2.0 개발 중 영향 없음)
- **`v2-dev` 브랜치:** V2.0 기능 개발 및 테스트 전용 브랜치 (완료 후 `main`에 Merge)

### 2) 데이터베이스 분리 (Supabase)
- **테섭(Staging):** 부계정으로 별도 Supabase 프로젝트 생성 → V2.0 테이블/컬럼 테스트용
- **본섭(Production):** V2.0 검증 완료 후 본섭 Supabase에 동일 스키마 반영
- **통합 서버 유지:** 웹 · 원스토어 · 구글플레이 유저 모두 **동일한 본섭 Supabase**를 공유하여 랭킹, 멀티플레이, 낚시터, 친구/DM을 함께 이용

### 3) 구글 플레이 앱 패키징 방식 (방식 3: 하이브리드)
- **로컬 번들링:** Capacitor로 `index.html`, `style.css`, `app.js`, `pixel_avatar.js`, `online.js`, `fishing.js` 등 앱 UI·엔진을 `.aab` 내부에 내장 (Target API 36 이상)
- **원격 데이터 로드:** `data.js` (`QUESTIONS_DB`)는 깃허브 JSON 또는 Supabase에서 불러오도록 분리하여 **신곡 추가 및 문제 수정 시 `.aab` 재빌드 없이 즉시 반영**

### 4) 플랫폼별 광고 어댑터 분기
| 실행 환경 | 감지 조건 | 하단 배너 | 보상형 광고 (3종) |
| :--- | :--- | :--- | :--- |
| **구글 플레이 (Capacitor)** | `Capacitor.isNativePlatform()` | **AdMob 배너** (쿠팡 숨김) | **Google AdMob 보상형** |

## 3. 홈 화면 & 플레이 흐름 개편

### 1) 홈 화면 통합
- 기존 `싱글 플레이` / `멀티 플레이` 버튼 2개를 **`[🎮 플레이]`** 버튼 1개로 통합
- 확보된 공간에 **`🎒 가방(인벤토리)`**, **`🎁 이벤트 · 출석`** 버튼 배치

### 2) 플레이 허브 페이지
- `[플레이]` 클릭 시 대형 배너 3종 표시:
  1. **🎯 싱글 플레이**
  2. **⚡ 1:1 멀티 플레이**
  3. **🏆 4인 멀티 플레이**

### 3) 싱글 플레이 & 무한도전 개편
- **아이템 사용:** 싱글 플레이는 기본 아이템 사용 가능
- **노템 보너스:** 아이템을 1개도 사용하지 않고 클리어 시 **획득 경험치(EXP) & CD +10% 추가 지급** (장착만 하고 안 썼으면 노템 인정)
- **무한도전 진정한 무한 모드:** 준비된 문제 풀(Pool)을 한 바퀴 다 풀면 다시 셔플하여 **중복 출제되더라도 하트가 0이 될 때까지 무한 진행**

### 4) 멀티 플레이 방 개편
- 방 생성 시 **[노템전 / 아이템전]** 옵션 선택
- 방 생성 후에도 대기방 내에서 **방장이 방 설정(연대/모드/단계/노템·아이템전) 변경 가능** (참가자 화면 실시간 반영 + 채팅창 시스템 알림)
- 멀티 아이템전에서는 **공용 아이템 3종(`3초 듣기`, `초성힌트`, `더블어택`)만** 사용 가능 (모드 전용 3종 비활성화)
